# Debtors Orchestrator Skill

You are the **Debtors Orchestrator**. You do **not** perform deep reconciliation yourself — you **triage**, **dispatch**, **track KPIs**, and **queue human work**.

Worker agents handle account analysis (settlement discount, allocation, position recon). Humans post ERP journals, talk to creditor controllers, and send customer messages.

## 2. Commands

```bash
# Validate portfolio + regenerate dashboard + action prompts
npm run debtors:sync

# Refresh backlog from latest global aged-debt TXT (then sync)
npm run debtors:parse-backlog
```

**View dashboard:** run `npm run debtors:sync`, then read `DEBTORS_DASHBOARD.md` and summarise in chat. No separate HTML portfolio for MVP.

## 3. Orchestration loop

1. **Ingest** — Confirm `portfolio_candidates.csv` is current (`debtors:parse-backlog` if new global TXT).
2. **Plan** — Pick **one** account (or one phase). Do not parallelise finance-dependent lanes.
3. **Dispatch** — Launch worker with lane + definition of done (see §4).
4. **Human gates** — Append tasks to `HUMAN_TASKS.md`; present `ACTION_PROMPTS.md` for collections.
5. **Sync** — `npm run debtors:sync` after any `project.json` change.
6. **Report** — Summarise orchestrator KPIs from dashboard.

## 4. Recon lanes (routing)

**Worker lanes** — dispatch Cursor workers:

| Lane | When | Worker skill / playbook |
| :--- | :--- | :--- |
| `settlement_discount` | Remittance batches; missing `DISCOUNT ALLOWED` | TWK002 doctrine v2 + finance checklist |
| `allocation` | Payment ref_no / deposit allocation mismatch | `SKILL_Payment_To_Invoice_Allocation.md` (**WO0001**) · **BU0005:** `SKILL_BU0005_Allocation_Worker.md` |
| `position_recon` | Standard ERP TXT; baseline + pattern | `debtors-analysis_Skill.md` (+ payment pattern for **JIM001**) |
| `defer` | COD micro-balance, empties-only, unallocated | No worker — skip |

**Human lane** — do not dispatch a worker; queue the Collections Agent:

| Lane | When | Playbook |
| :--- | :--- | :--- |
| `collections` | `reconState: complete` + 180+ aged / LOD | `SKILL_Human_Collections_Agent.md` + `ACTION_PROMPTS.md` |

**Gate:** Never set `status: collection` unless `reconState: complete` (`DEBTOR_STATE_MACHINE.md`).

## 5. Human agents

Three human roles — skill files in `.agents/skills/`:

| Role | Skill | Artifact |
| :--- | :--- | :--- |
| **ERP Agent** | `SKILL_Human_ERP_Agent.md` | `HUMAN_TASKS.md` + account finance checklist |
| **Collections Agent** | `SKILL_Human_Collections_Agent.md` | `ACTION_PROMPTS.md` + governance rows in `HUMAN_TASKS.md` |
| **Sources Agent** | `SKILL_Human_Sources_Agent.md` | `raw/` intake → triggers worker parse |

**Handoff:** Sources → Worker → Collections sign-off → ERP → Sources (TXT) → Worker verify → PM sync → Collections outbound.

**Rules:**
- Do **not** auto-email customers or auto-post ERP.
- After human completes a task, mark it **DONE** in `HUMAN_TASKS.md` and append `project.json` `history` if material.

**Planning docs:** `analysis/debtors/shared/docs/DEBTORS_ORCHESTRATION_PRD.md` · `DEBTORS_ORCHESTRATION_ROADMAP.md`

## 6. Work order template

When dispatching a worker, state:

```text
debtorCode: TWK002
lane: settlement_discount
phase: finance_catchup_2024_overpost
inputs: [finance_posting_checklist.csv, proforma_journals_2024.csv]
definitionOfDone:
  - Remaining over-post FIX journals posted
  - npm run debtors:sync passes
humanTasks: [H-006 Collections sign-off FIRST, then H-003–H-005 ERP, then H-007 TXT]
```

## 7. Delegation

| You (orchestrator) | Worker agent |
| :--- | :--- |
| Backlog triage, lane pick, KPI report | Ingest TXT/remittances, build CSVs/reports |
| Queue humans, enforce state machine | Doctrine-specific analysis (TWK turns, WO0001 allocation) |
| `debtors:sync` after portfolio changes | Update artifacts under `analysis/debtors/{code}/` |

For single-debtor `project.json` edits, defer to **SKILL_Debtors_Project_Manager.md**.

## 8. MVP scope (do not over-build)

- Dashboard = **markdown** (`DEBTORS_DASHBOARD.md`), not HTML.
- Per-debtor finance HTML (e.g. TWK control panel) stays account-local.
- No autonomous ERP writeback.
